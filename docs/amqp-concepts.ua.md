# Концепції AMQP - Advanced Message Queuing Protocol

## Що таке AMQP?

**Advanced Message Queuing Protocol (AMQP)** - це відкритий стандартний протокол додатку для middleware-орієнтованого обміну повідомленнями. AMQP забезпечує надійну, безпечну та ефективну передачу повідомлень між додатками.

## Основні компоненти AMQP

### 1. Брокер повідомлень (Message Broker)
- Центральний сервер, який маршрутизує повідомлення
- RabbitMQ - один з найпопулярніших AMQP брокерів
- Забезпечує персистентність, маршрутизацію та доставку повідомлень

### 2. Обмін (Exchange)
- Компонент, який отримує повідомлення від видавців
- Вирішує, в які черги відправити повідомлення
- Типи обмінів:
  - **Direct** - маршрутизація по точному збігу ключа
  - **Topic** - маршрутизація по шаблону ключа
  - **Fanout** - трансляція всім підключеним чергам
  - **Headers** - маршрутизація по заголовкам

### 3. Черга (Queue)
- Буфер, що зберігає повідомлення для споживачів
- Може бути довготривалою (durable) або тимчасовою
- Підтримує різні режими доставки

### 4. Прив'язка (Binding)
- Зв'язок між Exchange і Queue
- Визначає правила маршрутизації повідомлень
- Може містити ключі маршрутизації (routing keys)

### 5. Ключ маршрутизації (Routing Key)
- Атрибут повідомлення для визначення маршруту
- Використовується Exchange для прийняття рішення про маршрутизацію
- Підтримує патерни для Topic Exchange

## Переваги AMQP

### ✅ Надійність
- Підтверждення доставки (acknowledgments)
- Персистентність повідомлень
- Транзакційність операцій

### ✅ Гнучкість маршрутизації
- Різні типи Exchange для різних сценаріїв
- Складні правила маршрутизації
- Підтримка патернів і фільтрації

### ✅ Масштабованість
- Кластеризація брокерів
- Розподілена архітектура
- Балансування навантаження

### ✅ Безпека
- Аутентифікація та авторизація
- TLS/SSL шифрування
- Контроль доступу до ресурсів

## Практичні приклади використання

### 1. Обробка замовлень в e-commerce
```csharp
// Публікація замовлення
var order = new AmqpMessage(orderJson, "orders.exchange", "order.created");
await publisher.PublishAsync(order);

// Обробка в різних сервісах
// payment-service слухає "order.created"
// inventory-service слухає "order.created"  
// notification-service слухає "order.created"
```

### 2. Система логування
```csharp
// Різні рівні логів в різні черги
await publisher.PublishAsync(
    new AmqpMessage(errorLog, "logs.exchange", "log.error"));
await publisher.PublishAsync(
    new AmqpMessage(infoLog, "logs.exchange", "log.info"));
```

### 3. Мікросервісна архітектура
```csharp
// Команди між сервісами
var command = new AmqpMessage(
    commandData, 
    "commands.exchange", 
    "user.command.create"
);
```

## Налаштування в проекті

### 1. Конфігурація з'єднання
```json
{
  "RabbitMQ": {
    "HostName": "localhost",
    "Port": 5672,
    "UserName": "guest",
    "Password": "guest",
    "VirtualHost": "/",
    "Exchange": "messaging.exchange",
    "ConnectionTimeoutSeconds": 30
  }
}
```

### 2. Створення повідомлення
```csharp
var message = new AmqpMessage(
    payload: jsonData,
    exchange: "user.exchange",
    routingKey: "user.created",
    messageType: MessageType.Event,
    source: "user-service"
)
{
    Priority = 1,
    Persistent = true,
    Expiration = 60000 // 60 секунд
};
```

### 3. Валідація повідомлення
```csharp
if (message.IsValid())
{
    // Повідомлення готове до відправки
    await publisherService.PublishAsync(message);
}
```

## Порівняння з іншими протоколами

| Критерій | AMQP | MQTT | HTTP |
|----------|------|------|------|
| **Надійність** | Висока | Середня | Низька |
| **Швидкість** | Висока | Дуже висока | Середня |
| **Складність** | Висока | Низька | Середня |
| **Маршрутизація** | Гнучка | Проста | Відсутня |
| **Розмір заголовків** | Середній | Малий | Великий |

## Сценарії використання AMQP

### ✅ Коли використовувати:
- Критично важливі бізнес-процеси
- Складна маршрутизація повідомлень
- Потреба в транзакційності
- Мікросервісна архітектура
- Системи з високими вимогами до надійності

### ❌ Коли не використовувати:
- Прості одноразові операції
- IoT пристрої з обмеженими ресурсами
- Потреба в мінімальній затримці
- Простий request-response патерн

## Моніторинг та відлагодження

### Ключові метрики:
- Кількість повідомлень в чергах
- Швидкість публікації/споживання
- Кількість неподтверджених повідомлень
- Час життя з'єднань

### Інструменти:
- **RabbitMQ Management UI** - веб-інтерфейс брокера
- **Grafana** - візуалізація метрик
- **Prometheus** - збір метрик
- **k6** - навантажувальне тестування

## Рекомендації з продуктивності

### 1. Оптимізація повідомлень
- Використовуйте компактні формати (JSON, Protocol Buffers)
- Встановлюйте TTL для повідомлень
- Групуйте малі повідомлення в батчі

### 2. Налаштування черг
- Використовуйте durable черги для важливих даних
- Налаштуйте prefetch для споживачів
- Моніторте розмір черг

### 3. З'єднання
- Використовуйте connection pooling
- Налаштуйте heartbeat intervals
- Реалізуйте reconnection logic
